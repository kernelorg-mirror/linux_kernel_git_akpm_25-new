Subject: net: copy pagecache data when socket splice hits refcount limit
Date: Sat, 07 Nov 2026 21:49:08 -0800

The pagecache refcount checks in the five-patch series cover insertion
into a pipe, but a pipe buffer can subsequently supply the same page to an
skb.  skb_append_pagefrags() takes another reference without checking the
limit.  TCP receive splice similarly takes a reference when transferring
an skb fragment into a pipe.  Local users can reach both paths through
ordinary sockets and splice().

Refuse the extra skb reference at the limit and copy the source page into
a private page in skb_splice_from_iter().  Checksum the actual page
attached to the skb.  On the receive side, copy into the socket's page
fragment instead of retaining another reference to the original page.  If
the copy cannot be allocated, return an error when no bytes were spliced;
preserve the partial byte count otherwise.  Some callers map the error to
their own splice errno.

The checks only precede new references.  Coalescing with an existing skb
fragment or pipe buffer remains possible without another folio ref.  This
depends on folio_ref_count_over_limit() in the preceding series.  The send
copy uses atomic allocation because this helper also serves sockets that
do not permit sleeping allocations.
