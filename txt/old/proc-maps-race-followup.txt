Subject: selftests/proc: fix proc-maps-race setup and RSS coverage
Date: Wed, 04 Nov 2026 03:16:47 +0000

If fork() fails, or the modifier exits while setting up its VMAs, the
parent waits for CHILD_READY until the 30-second harness timeout.  Check
fork() and have the modifier report readiness through a pipe.  An early
exit closes the write end and wakes the parent even if the modifier could
not report an error.

Only the smaps split and resize tests compare RSS.  Keep the three maps
tests and the smaps remap test running when the locked memory allowance is
too small.  Pass the mlockall() error to the parent so the two tests which
need locked pages can report a skip.

MAP_POPULATE can leave pages absent, and reclaim can remove pages before
mlockall(MCL_ONFAULT).  A skipped VMA with no resident pages contributes
nothing to the RSS comparison.  Fault in each test page with a write after
locking the mappings and before making alternate VMAs read-only.  This
gives the rollup check resident pages to count.

Applies on top of Suren Baghdasaryan's v3, message ID
20261104015447.363602-1-surenb@google.com.

Tested v3 alone and with this fixup on the same x86-64 Debian guest
running Linux 7.4.0-rc1. All six proc-maps-race cases passed on both
versions with the default flags and again with READ_IMPLIES_EXEC.

Without CAP_IPC_LOCK, I set RLIMIT_MEMLOCK to zero and then to 64 KiB.
At each limit v3 skipped all six cases. With the fixup the three maps
cases and the smaps remap case passed. Only smaps split and resize
skipped. Those two require locked pages for their RSS comparisons.

In diagnostic builds I forced the modifier fork() to fail, then forced
mmap() and mprotect() to fail separately during child setup. Each v3
run hit the 30-second harness timeout. With the fixup each run reported
a test failure in 12 to 14 ms.

To check what the RSS comparison covered, I used MADV_DONTNEED on all
129 three-page mappings just before mlockall() in the smaps split case.
At child readiness, mincore() found 0 of 387 test pages resident on v3
and all 387 with the fixup. Both runs passed the RSS comparison.
