Subject: mm/mempolicy: use one node set for interleave weights
Date: Sun Oct 25 01:03:44 PM PDT 2026

Switching weighted interleave back to automatic mode while memory is being
onlined can cause a kernel divide error on x86, and a panic if
panic_on_oops is set.

reduce_interleave_weights() scans N_MEMORY three times.  Its caller holds
wi_state_lock, which protects the bandwidth table and weights but does not
prevent memory hotplug from changing N_MEMORY.  If the first pass sums
zero bandwidth, a returning node with previously recorded positive
bandwidth can enter the next pass and cause a division by zero.

Record the nodes visited while summing their bandwidth, then use that same
set when scaling and reducing the weights.  The arithmetic remains
consistent even if hotplug changes N_MEMORY during the first pass.  This
needs no additional locking and remains usable from hotplug callbacks.
