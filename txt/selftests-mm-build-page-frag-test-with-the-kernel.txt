Subject: selftests/mm: build the page fragment test with the kernel
Date: Thu, 08 Oct 2026 17:49:06 -0700

The page fragment selftest builds page_frag_test.ko as an external module
under tools/testing/selftests/mm.  With CONFIG_TRIM_UNUSED_KSYMS=y, the
kernel build cannot account for its symbol references.  Exports needed by
the test, such as __cpu_active_mask, can therefore be trimmed before the
selftest module is built, causing modpost to fail.

Building the module from the userspace selftest Makefile also uses the
selftest compiler.  This need not be the compiler used for the kernel: for
example, a nolibc cross compiler can build the kernel but cannot link the
userspace tests, while the native compiler may not support the flags
recorded in the kernel configuration.

Move the module to lib/test_page_frag.c and add CONFIG_TEST_PAGE_FRAG so
that it is built with the kernel and its references are visible to the
normal symbol-trimming pass.  Restrict the option to modules because the
test is invoked explicitly with parameters and returns -EAGAIN after
running, rather than remaining loaded.

Add CONFIG_TEST_PAGE_FRAG=m to tools/testing/selftests/mm/config.  This
file is a kernel configuration fragment listing settings needed by the MM
selftests.  make kselftest-merge merges the fragments from all selftest
directories into the existing kernel .config and runs olddefconfig.  Run
it before building the kernel and modules so that modpost sees the test
module's references and retains the required exports.  Building the
userspace selftests alone does not merge the fragment or enable
CONFIG_TEST_PAGE_FRAG.

Remove the external module build rules and update test_page_frag.sh to
load the installed test_page_frag module with modprobe.  Install the
module for the kernel under test with make modules_install.  Keep the test
implementation and its parameters unchanged.

There are 21 other kernel modules under tools/testing/selftests/.  All are
vulnerable to this.  A more general solution would be good.

It's unfortunate that the operator needs to run "make kselftest-merge"
before building the kernel.  Disabling CONFIG_TRIM_UNUSED_KSYMS is easier.

An alternative is to populate CONFIG_UNUSED_KSYMS_WHITELIST in Kconfig so
certain symbols don't get trimmed.  But that's another
do-before-building-kernel step.

We could perhaps ship a whitelist file for selftests alongside the
user-defined CONFIG_UNUSED_KSYMS_WHITELIST.  To prevent trimming of
symbols which we know selftests needs.
