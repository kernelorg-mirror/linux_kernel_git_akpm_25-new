From: Andrew Morton <akpm@linux-foundation.org>
Subject: kernfs: make ->getattr() lockless
Date: Fri, 27 Nov 2026 15:40:00 -0800

stat() on a kernfs file no longer takes a lock in the path walk, but
kernfs_iop_getattr() still takes kernfs_iattr_rwsem for reading on every
call.  All it needs the lock for is to refresh the mode and owner in the
inode before generic_fillattr() copies them out.  The times and the link
count are read from the node and need no lock.

So do what kernfs_iop_permission() now does: inside a read section of
root->iattr_seq, check that the inode's mode and owner are those of the
node, and if they are, fill in the kstat without the lock.  If a setattr
is running, or started meanwhile, or the inode is stale, take the lock and
refresh as before.

The comparison moves into kernfs_inode_current() so that both callers
use it.

On top of kernfs-path-lookup-scalability-improvements.patch (your copy
with the kernfs_free_rcu() comment moved), which is on mm-new
3d27e49eb905 plus Shakeel's six.

Compile-tested only: fs/kernfs/ builds with x86_64 defconfig, no
warnings.  Nothing was run.  The changelog has no figures because there
are none yet.

For a quick test, A = the queue with the path lookup patch, B = A plus
this:

  kt perf stat 64 5 /sys/fs/cgroup/t/p*/cgroup.procs        (was 17.6M/s)
  kt perf stat 64 5 /sys/fs/cgroup/t/a/b/c/d/cgroup.procs   (was 8.65M/s)
  kt perf stat 1  5 /sys/fs/cgroup/t/a/b/c/d/cgroup.procs
  kt perf access 64 5 /sys/fs/cgroup/t/p*/cgroup.procs      (control)

and the convoy test, case d (the monitor calls stat() before open()),
which stalled for up to 556 ms.  It should now behave like case c.

Before this is believed, the chown race needs a stat() in it: a reader
calling stat() on the mode-0007 directory while its owner flips must
never see uid 1000 with gid 1000.  kt race does not do that today.

generic_fillattr() also reads i_ino, i_rdev, i_size, i_blocks and
i_nlink from the inode.  kernfs does not change the first four after
the inode is set up, and the link count is overwritten from the node
for directories, as before.  I checked that by reading, not by test.
