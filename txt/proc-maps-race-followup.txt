Subject: selftests/proc: fix proc-maps-race setup and RSS coverage
Date: Wed, 04 Nov 2026 03:16:47 +0000

If fork() fails, or the modifier exits while setting up its VMAs, the
parent waits for CHILD_READY until the 30-second harness timeout.  Check
fork() and have the modifier report readiness through a pipe.  An early
exit closes the write end and wakes the parent even if the modifier could
not report an error.

Only the smaps split and resize tests compare RSS.  Keep the three maps
tests and the smaps remap test running when the locked memory allowance is
too small.  Pass the mlockall() error to the parent so the two tests which
need locked pages can report a skip.

MAP_POPULATE can leave pages absent, and reclaim can remove pages before
mlockall(MCL_ONFAULT).  A skipped VMA with no resident pages contributes
nothing to the RSS comparison.  Fault in each test page with a write after
locking the mappings and before making alternate VMAs read-only.  This
gives the rollup check resident pages to count.
