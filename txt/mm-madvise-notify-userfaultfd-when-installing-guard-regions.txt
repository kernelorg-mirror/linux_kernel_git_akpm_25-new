Subject: mm/madvise: notify userfaultfd when installing guard regions
Date: Sat, 21 Nov 2026 18:49:58 -0800

MADV_GUARD_INSTALL can discard the contents of an anonymous range before
installing guard markers. A userfaultfd manager with MISSING registration
does not receive a remove event. If it retains a copy of the discarded
contents, it can supply that old data when the guard is removed and the
next access faults, instead of treating the range as discarded. The same
operation also drops uffd-wp and RWP markers without telling a manager
that it might need to adjust its write tracking.

Send UFFD_EVENT_REMOVE before installing the guards, as MADV_DONTNEED
does. If the event drops mmap_lock, reacquire it and look up and validate
the VMA again before modifying it. Limit the current operation to the
revalidated VMA; madvise_walk_vmas() handles any remaining range.

Tal Zussman previously proposed this notification [1]. This version is
based on the tree containing Lorenzo Stoakes's marker-dropping fix [2].
The stale-data path has not yet been reproduced by this review; this
patch is for A/B testing with a manager that retains old page contents.
